Here's the schema (`src/db/schema.ts`) as an ERD, plus a full static-vs-DB breakdown of the UI.

## ERD

```
┌────────────────────────┐
│         users           │
├────────────────────────┤
│ id             PK (uuid)│
│ name                    │
│ email          UNIQUE   │
│ password_hash           │
│ created_at               │
└───────────┬─────────────┘
            │ 1
            │ has many
            │ *
┌───────────▼─────────────┐
│         orders            │
├──────────────────────────┤
│ id               PK       │
│ user_id          FK → users.id
│ status           (pending|paid|fulfilled|cancelled)
│ total_cents                │
│ stripe_session_id           │
│ shipping_name                │
│ shipping_address  (jsonb)     │
│ created_at                    │
└───────────┬───────────────────┘
            │ 1
            │ has many
            │ *
┌───────────▼───────────────────┐        ┌───────────────────────────┐
│         order_items              │        │          products            │
├─────────────────────────────────┤        ├───────────────────────────┤
│ id                   PK          │        │ id               PK (uuid) │
│ order_id             FK → orders.id       │ slug             UNIQUE    │
│ product_id           FK → products.id ───►│ title                      │
│ title_snapshot                    │        │ description                │
│ image_url_snapshot                │        │ price_cents                │
│ price_cents_snapshot              │        │ category                   │
│ quantity                          │        │ image_url                  │
└───────────────────────────────────┘        │ rating                     │
                                              │ review_count               │
                                              │ stock                      │
                                              │ created_at                 │
                                              └────────────────────────────┘
```

Relationships: `users 1─* orders`, `orders 1─* order_items`, `products 1─* order_items`.

**No `cart_items` table** — that's the deliberate scope cut from the README: cart lives entirely in `localStorage` via React context (`src/lib/cart-context.tsx`), never touches the DB until checkout, at which point `order_items` snapshots the title/image/price at time of purchase (so an order's history stays accurate even if a product's price or catalog listing later changes).

Auth sessions are **JWT cookies, not a DB table** — Auth.js signs the session into a cookie (`AUTH_SECRET`), so there's no `sessions` row to look up on every request.

## Static vs. DB-populated

| Area | Source |
|---|---|
| Product catalog (title, price, description, image URL, rating, stock) | **DB** — `products` table, via `src/db/seed.ts` |
| Category nav links (Books, Electronics, …) | **DB** — `SELECT DISTINCT category FROM products` (`getCategories()`), not hardcoded |
| Homepage/search product grid | **DB** — `getProducts({ q, category })` |
| PDP content | **DB** — `getProductBySlug()` |
| User accounts | **DB** — `users` table, written on signup |
| Session/login state | **Not DB** — JWT in a signed cookie |
| Orders + order history + order detail | **DB** — `orders` / `order_items`, written at checkout |
| Cart contents | **Not DB** — `localStorage` only, client-side React context |
| Navbar logo, search bar chrome, hero banner text, footer disclaimer | **Static** — hardcoded JSX in `navbar.tsx` / `page.tsx` / `layout.tsx` |
| Product images themselves | **DB-referenced, static-hosted** — `products.image_url` points to `picsum.photos` placeholder URLs (no real image upload pipeline, per the stated scope cut) |
| Stripe test-card hint text on checkout | **Static** — hardcoded string |
| Star rating stars (★☆☆☆☆) | **Computed client-side** from the DB `rating` value, not stored as rendered markup |
